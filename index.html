01 · ԽՆԴԻՐԸ

Ինչ հարցերի էր պետք պատասխանել

Դեղերի մեծածախ դիստրիբյուտորն ունի մի քանի պահեստ, մանրածախ և մեծածախ հաճախորդներ և գործարքների մանրամասն գրանցում։ Նպատակն էր հասկանալ, թե որտեղից է գալիս շահույթը և որտեղ է այն կորչում։

Վերլուծությունը ծածկում է պահեստների արդյունավետությունը, ամենաշահութաբեր ապրանքները, հաճախորդների խմբերի համեմատությունը, ամսական դինամիկան, զեղչերի ազդեցությունը և, ամենամանրամասն, վերադարձների պատճառներն ու հետևանքները։

Տվյալները ուսումնական են, աշխատանքը կատարված է Oracle APEX միջավայրում։

06 · ԸՆՏՐՎԱԾ SQL

Ինչպես է հաշվված

Ստորև երեք հարցում, որոնք ցույց են տալիս տարբեր տեխնիկաներ։

Ամենամեծ գործարքը յուրաքանչյուր հաճախորդի համար

KEEP (DENSE_RANK FIRST)

Մեկ անցումով գտնում է և՛ առավելագույն գումարը, և՛ այդ գործարքի ամսաթիվը՝ առանց լրացուցիչ join-ի։

SELECT
    C.name AS customer_name,
    MAX(TX.total_amount) AS max_transaction_amount,
    MAX(TX.transaction_date) KEEP (DENSE_RANK FIRST ORDER BY TX.total_amount DESC) AS transaction_date
FROM (
    SELECT T.customer_id, T.transaction_date,
           SUM(D.total_amount) AS total_amount
    FROM P_Transactions T
    JOIN P_TransactionDetails D ON D.transaction_id = T.transaction_id
    WHERE T.transaction_type = 'Իրացում'
    GROUP BY T.customer_id, T.transaction_id, T.transaction_date
) TX
JOIN P_Customers C ON C.customer_id = TX.customer_id
GROUP BY C.customer_id, C.name
ORDER BY max_transaction_amount DESC;

Միջինից թանկ ապրանքներ

AVG(AVG()) OVER ()

Window ֆունկցիան ագրեգատի վրա տալիս է ապրանքների միջին գների միջինը նույն հարցման մեջ, այնպես որ յուրաքանչյուր ապրանք ունի հավասար կշիռ՝ անկախ վաճառքի քանակից։

SELECT code, name, avg_selling_price, overall_avg_price
FROM (
    SELECT
        P.code,
        P.name,
        ROUND(AVG(D.selling_price), 2) AS avg_selling_price,
        ROUND(AVG(AVG(D.selling_price)) OVER (), 2) AS overall_avg_price
    FROM P_TransactionDetails D
    JOIN P_Transactions T ON T.transaction_id = D.transaction_id
    JOIN P_Products P ON P.product_id = D.product_id
    WHERE T.transaction_type = 'Իրացում'
    GROUP BY P.product_id, P.code, P.name
)
WHERE avg_selling_price > overall_avg_price
ORDER BY avg_selling_price DESC;

01 · THE PROBLEM

The questions that needed answers

A pharmaceutical wholesaler runs several warehouses, serves retail and wholesale customers, and records every transaction line in detail. The goal was to understand where profit comes from and where it leaks.

The analysis covers warehouse performance, the most profitable products, customer-segment comparison, monthly trends, the effect of discounts and, in most depth, the causes and consequences of returns.

Educational dataset; the work was done in Oracle APEX.

03 · KEY INVESTIGATION

Returns: two cases, 87% of the returned amount

The share of profit lost (13.75%) is higher than the share of revenue lost (11.25%), meaning the returned goods were relatively high-margin. The losses are concentrated in just two cases.

Sterile bandage: 100% returned

Nor Deghatun pharmacy returned the entire batch of 500 units, costing AMD 25,000 in profit. On top of that, this customer has zero recorded purchases, so the return was logged without a matching sale: either a quality problem or a data error.

Vitamin C: expired delivery

Medical Center N1 received expired stock (AMD 17,500), which gave this customer the highest return rate at 32.41%. It is a warehouse-management gap that is easy to prevent.

Data quality

“Full return” and “Partial return” are return types, not reasons, so the real cause of the largest returns is unknown. “Partly” and “Partial” mean the same thing but are recorded separately.

04 · RECOMMENDATIONS

What to do

1

Investigate the bandage case

Inspect the batch, file a claim with the supplier if quality is at fault, and locate the original sales document.

2

Control expiry dates

Apply first-expired, first-out (FEFO) and sell near-expiry stock at a discount.

3

Verify orders before shipping

Confirm each order with the customer by product code and dosage.

4

Set clear return rules

Accept returns only with a reference to the sales document and within a set period.

5

Standardize return reasons

Replace free text with a pick list: expired, quality defect, damaged packaging, wrong delivery, overstock.

06 · SELECTED SQL

How it was calculated

Three queries that show different techniques. Filter values are in Armenian: ‘Իրացում’ means sale.

Largest transaction per customer

KEEP (DENSE_RANK FIRST)

Finds both the maximum amount and that transaction’s date in a single pass, with no extra join.

SELECT
    C.name AS customer_name,
    MAX(TX.total_amount) AS max_transaction_amount,
    MAX(TX.transaction_date) KEEP (DENSE_RANK FIRST ORDER BY TX.total_amount DESC) AS transaction_date
FROM (
    SELECT T.customer_id, T.transaction_date,
           SUM(D.total_amount) AS total_amount
    FROM P_Transactions T
    JOIN P_TransactionDetails D ON D.transaction_id = T.transaction_id
    WHERE T.transaction_type = 'Իրացում'
    GROUP BY T.customer_id, T.transaction_id, T.transaction_date
) TX
JOIN P_Customers C ON C.customer_id = TX.customer_id
GROUP BY C.customer_id, C.name
ORDER BY max_transaction_amount DESC;

Products priced above average

AVG(AVG()) OVER ()

A window function over an aggregate returns the average of per-product averages in the same query, so every product carries equal weight regardless of sales volume.

SELECT code, name, avg_selling_price, overall_avg_price
FROM (
    SELECT
        P.code,
        P.name,
        ROUND(AVG(D.selling_price), 2) AS avg_selling_price,
        ROUND(AVG(AVG(D.selling_price)) OVER (), 2) AS overall_avg_price
    FROM P_TransactionDetails D
    JOIN P_Transactions T ON T.transaction_id = D.transaction_id
    JOIN P_Products P ON P.product_id = D.product_id
    WHERE T.transaction_type = 'Իրացում'
    GROUP BY P.product_id, P.code, P.name
)
WHERE avg_selling_price > overall_avg_price
ORDER BY avg_selling_price DESC;
